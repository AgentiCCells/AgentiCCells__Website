# ACC-027 · The site factory: a request in a commit creates a site
Owner: conductor@AgentiCCells.dinis, then factory@AgentiCCells.dinis · Status: Waits on Dinis (repositories being created; then credentials)
Source: Dinis, 2026-11-15 ~20:30 UTC, a draft newsroom article given in this session: "From a commit to a live website: a site factory where a request file in a commit makes a CI pipeline create the GitHub repository, the DNS record and the sgit vault, seed a page, check HTTPS, run a first pass with Claude Code, and record it all, so an agent can create sites by committing". And: "Should we create a new session here and GitHub repo (what name you recommend) to wire this up and test it out".
Dinis's words: "A request is a folder: a site file and a brief, committed to a control repository; the pipeline writes the result back." "Plan on the pull request, apply on merge." "Good credentials: a GitHub App and OpenID Connect for AWS, with no long-lived keys in the pipeline." "Public by default: the control repository and its record are public; only the credentials are not." "An agent can drive it by committing a request." "This is a hypothesis and an architecture, not yet built; the AgentiCCells team is the natural place to build it."
Repositories (agreed with Dinis, 2026-11-15 ~20:45, "yeah I agree let me create those"): AgentiCCells/AgentiCCells__Site__Factory (the public control repository), AgentiCCells/AgentiCCells__Site__Template (the seed every new site is created from, taken from this site's build, gates and workflow), AgentiCCells/AgentiCCells__Site__Website (the website at agenticcells.site, the factory's first test request), and AgentiCCells/AgentiCCells__Site__Hub if the hub gets its own. Dinis creates them; the conductor starts factory@ once they exist. A new interactive role factory@AgentiCCells.dinis builds it; pipeline@'s map/site-creation.md is its specification.
Build order (proposal): 1. request schema and validator (site.json, brief.md); 2. the plan job on pull requests, with no secrets; 3. the apply job as a dry run that writes status.json; 4. one real step at a time as each credential arrives (GitHub App, then AWS OIDC role for the customer-site zone, then the sgit token, then optionally a Claude key); 5. teardown pipeline; 6. its Agent Behaviour Policy (abp@).
