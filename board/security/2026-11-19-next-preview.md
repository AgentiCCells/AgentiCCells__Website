## Medium
1. **Ownership said as a fact before hand-over.** next/copy.json promise "You own it": "Your site is a GitHub repository in your name ... Nothing of yours stays with us." The security page and FAQ say the site is in our account until hand-over, and no-lock-in.md says the three-month hand-over is "an expectation ..., not yet a rule in the terms". Fix: "After hand-over, your site is a GitHub repository in your name." [writer]
2. **"No terms but yours."** next/copy.json (promise "No lock-in" and line 85, "no terms but yours apply"). GitHub's Terms of Service, the registrar's terms and the Claude plan's terms still apply. Fix: "no platform terms from us; only your host's and registrar's, which you choose." [writer]
3. **GitHub Pages wording is narrower than GitHub's page.** Ours (copy.json, no-lock-in.md, pricing.md, faq): free "when the repository is public and the site is not an online shop or a site for business transactions". GitHub's page, read today (docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits): Pages "is not intended for or allowed to be used as a free web-hosting service to run your online business, e-commerce site, or any other website that is primarily directed at either facilitating commercial transactions or providing commercial software as a service (SaaS)", should not carry "sensitive transactions like sending passwords or credit card numbers", and has a soft bandwidth limit of 100 GB a month. "Run your online business" is the phrase most of our buyers (small businesses) meet, and we leave it out. Fix: quote GitHub's sentence verbatim with the link and date, and add "whether a small business site qualifies is GitHub's decision; if unsure, use another static host". [writer]
4. **Privacy claim leaves out the host's logs.** sovereignty.md "Privacy-first, European-aligned" and "no tracking by us, so there is nothing to put behind a banner". GitHub's own page (what-is-github-pages, read today): "When a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes." GitHub is a US company. Fix: one sentence that the host keeps visitor IP addresses under its own privacy statement, and that a European host is an option. [writer]
5. **What the security page does not protect against is incomplete.** next/pages/security.md lists GitHub account, registrar, your Claude, what you add, what you publish. Missing: (a) the email account behind GitHub and the registrar (account recovery goes through it); (b) a partner or anyone you give repository access to; (c) a Claude session that is tricked by what it reads (a web page, an email, a file) rather than by what you ask; (d) GitHub itself: an outage, a suspension under its terms; (e) before hand-over, our GitHub organisation and our agents. The FAQ "Is it secure?" names only GitHub and the registrar. Fix: add (a) to (e) as one line each, and in the FAQ add "and the email account behind them". [writer]
6. **CI lets a failed commit deploy on the next push, and checks no signature.** build/check-commits.mjs checks only the pushed range (before..after). Six commits (ee150e6 ... d9f7f53) failed the Agent: check, then deployed with 1259501 because the next push's range did not include them (team/rounds/1.md). CI does not run `git verify-commit`, so an unsigned commit would deploy too. Fix (strengthens, does not weaken): check every commit not yet deployed (from the last deployed sha), and verify SSH signatures against team/keys in CI. Needs Dinis's word on the dot-or-hyphen trailer first. [developer] [conductor]

## Low

Fix: the same /^(https?:|\/|#)/ test in inline() and on example urls. [developer]
