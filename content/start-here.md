# Start here

You want an agentic team. Many people talk about doing this. We do it, and this page says where to start. You do not need the big version first.

Begin with a very simple workflow and grow only when it earns it. Everything we write here is open source, with no lock-in.

**Already run agents and need to control them?** Go to [riskmandate.ai](https://riskmandate.ai), which writes the behaviour policy and sells on the same ladder. Come back here when you want a team set up with its policies.

## Step one: one very simple workflow

Pick one piece of work that repeats. Give it to one Claude agent on a loop, with a written instruction, a place to put its results and a person who checks them. That is the smallest cell. It is a proposal for where to begin, not a product.

If you would rather not set it up, the [website cell](/website-cell/) is the simplest thing we run for you: £500, one-off, first proposal, not an offer. There are no meetings and little of your time. A team of agents builds a public website that you steer from your browser. Nothing has been sold yet, and the end-to-end flow is being built now.

Three very simple workflows to pick from. Each is one agent, one instruction, one place for results and one person who checks:

- **A weekly digest.** The agent reads the sources you name and writes one page of what changed, for you to read and send yourself.
- **A draft inbox.** The agent drafts replies to the same few kinds of message. A person edits and sends every one; the agent never sends. Our [email cell](https://hub.agenticcells.site/cells/cell-email/) is an example, listed on the hub as a demo.
- **A website for you.** The [website cell](/website-cell/) above, and the [job-seeker cell](/job-seeker-cell/), a proposal that does not exist yet.

These are suggestions for where to begin, not products we have sold.

Whatever you run, an agent that sleeps and wakes needs five things: an inbox, timers, memory, permissions and an outbox. [We run all five in our own team](/our-team-as-a-cell/), as files in one repository.

## Step two: add a meeting or two

When one workflow works, a few sessions add more roles, a shared board and a handover into your own accounts. We would prepare, meet you twice, do the work, present it and hand it over. From £1,500, first proposal (prices: [The intersection](https://newsroom.sgit.ai/articles/the-intersection.html), 2026-11-16).

## Step three: a team

Two days of engagement, with more of our time and maybe some travel: a conductor, several agents, a key for each and a board as files. £5,000, first proposal.

## Step four: a network

A customer engagement, where we map your work and deliver a whole set of things: several teams of agents, each with its own lead agent, plus policies and a record you can read. £20,000, first proposal.

The [cells page](/cells/) has the same four steps, and what each site sells at each step. [riskmandate.ai](https://riskmandate.ai) sells agent behaviour policies on the same ladder. If your first need is to control agents you already run, start there.

## What it looks like at scale

Our own team ran many agents at Web Summit in Lisbon. The counts below come from one public article, [Ten days at Web Summit](https://newsroom.sgit.ai/articles/ten-days-at-web-summit.md), which counted them from git history and the session list. It says the counts depend on how you count, and that an "agent" means a distinct name in commits.

- Around 250 named agents, across about 20,000 commits in 15 repositories ([the article](https://newsroom.sgit.ai/articles/ten-days-at-web-summit.md)).
- 224 Claude Code sessions, more than 60 of them at once at the peak ([the article](https://newsroom.sgit.ai/articles/ten-days-at-web-summit.md)).

This is our own team's work, not a customer's, and it is a measure of activity, not of quality.
