## In one paragraph

Dinis asked for the team to run on a schedule (ACC-020). Getting a scheduled agent to push took three attempts between 17:10 and 17:47: a scheduled task that fired its own session could clone but not push; a fix that had the session attach the repository itself failed because the tool to attach was not there; a run started by the conductor with the repository already attached worked first time. Its own release of that work reached `dev` at 18:08 and was stopped by CI's leak scan; the scan was not loosened, the log was fixed, and a single release command now runs every gate with no pipes.

## The schedule, three ways

1. **A scheduled task fires its own fresh session.** Each run gets its own container. It failed because a session started this way has the code but not the right to push it. Found by the first test, which reported the 403.
2. **The fresh session attaches the repository itself.** One extra step, limited to this one repository, on Dinis's rule "everybody can push to dev". It failed because the session did not have the tool to attach. Found by the second test.
3. **The conductor starts each run with the repository attached.** The conductor's hourly wake goes to the conductor's own session, which already holds the repository (team/SCHEDULE.md), and it now starts the roles. This worked first time and is how this report was written.

What it cost: one lost run, and the ten role scheduled tasks paused (team/SCHEDULE.md). What it changed: each run still gets its own session and container, so part of the shared-container gap closes for these runs (team/SCHEDULE.md; board/abp/README.md gap 2).

## The release the gates blocked

The gates did their job twice in one minute. The validator refused an unmarked price before commit; CI refused the push after it. Neither gate was weakened. The real fault was in the step around the gates: a pipe that let a failed check look like a pass on the conductor's side. The fix was to stop piping gates at all, written into one command and into COMMON.md ("Never pipe a gate into another command: a pipe hides its exit code"). Evidence: ca872d4, eb80874, e3bfef3.

For a buyer this is the point of the gates: a mistake by the conductor, the agent that briefs all the others, still did not reach the live site.

## The first offering, and this site as its first instance

Dinis's article sets out the £500 website cell (first proposal) in seven steps: order, queue, build, preview, key, steer, handover, "and none of them needs me on a given day". It also says what it does not claim: "The prices and the flow are a proposal: the steps exist as pieces, and the end-to-end flow is being built now by AgentiCCells' own team."

map/website-cell.md maps each step against REALITY.md. In short: build exists (this site); queue and the hourly wake exist for the team's own work; order, the browser key, the vault lane for steering, previews on agenticcells.app and handover do not exist yet.

"We are our own first customers." This site is the first instance: ordered by Dinis's brief, queued on the board, built by the team, live on agenticcells.com rather than a preview subdomain, steered by Dinis through briefs and newsroom articles rather than a signed lane, and with no handover needed. The gap between those two columns is the work in ACC-021.
